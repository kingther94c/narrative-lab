## 七项修订

### 1. fine-tuning 换基础模型

探针测到的、12 GiB 预算内 LoRA 能训练的最长序列：

| 模型 | 最长序列 | 该长度的峰值内存 |
|---|---|---|
| Qwen3.5-4B | 512 | 10.2 GiB |
| Qwen3.5-9B | 256 | 7.7 GiB |
| Gemma 4 12B | 2,048 | 11.1 GiB |
| DianJin-R1-7B（Qwen2.5 底座） | 4,096 | 8.6 GiB |

一个段落对加上标注说明和输出大约 1–2k token，Qwen3.5 训不了。原因在 mlx_lm：训练时 Gated DeltaNet 层只能逐 token 循环。

修订：

- 全析因放在两个普通注意力的模型上：**Qwen2.5-7B-Instruct** 和 **Gemma 4 12B**。
- Qwen2.5-7B-Instruct 的 LoRA 可行性已经在它的衍生模型 DianJin 上测过。DianJin 也因此成为“同一底座、别人做过领域训练”的严格对照。它需要下载约 5 GB，要你同意；下载之前只用已在盘上的 Gemma 4 12B。
- Qwen3.5-4B 和 9B 保留，但和商业模型一样只跑不含 fine-tuning 的 12 个组合。
- 训练样本上限 2,048 token。
- 不建议提高内存预算：4B 在 1,024 上预测要 20 GiB，接近 Metal 约 25 GiB 的上限，实际试跑一次已经崩溃。

### 2. 标签方案

- 变化标签拆成两个属性：方向（上调、维持、下调）和区间宽度（收窄、不变、放宽）。另有四种状态：首次给出、明确撤回、不再提及、未给指引。这样“区间既移动又收窄”有确定的标签。
- 明确撤回和悄悄不再提及分开。临时暂停、季度指引改成年度指引各有规则。
- 指标不限于 EPS，覆盖收入、利润率、资本开支。
- 定性指引是核心分层，不是附带。数值 EPS 指引只占新闻稿前瞻性句子的约 5%；不确定性上升时公司会撤掉数字、改用文字，临近失败的公司集中在这里。区分度试跑从这一层开始。
- 对照对加入未改动的对照样本，报告误报率。一对里的两个版本分开给模型，事后再算一致性。无效输出怎么计分预先登记。
- 测试集按公司的更新习惯分层：每季都更新的公司上调多于下调，偶尔更新的公司相反。
- 增加两个基线：关键词规则；文本相似度加词典语气变化。

### 3. Level 2 的锚放在结果一侧

v1 写的是“只做有数值锚的版本”。如果只收数值指引，样本会系统性漏掉临近失败的公司。修订为：锚在结果上，不在指引上。定性指引也进入 Level 2，对照的是下一季按申报值计算的同一指标，检验按数值变化幅度分层。已有研究里这类关联很弱，所以要用全样本。

### 4. 标注门槛

- kappa 不低于 0.8 在 100 条上不是可靠的门槛：真值 0.79 也有约 45% 的概率通过。改为看区间下限，同时报告原始一致率和 AC1，因为“维持”一类会占多数。
- 单人金标不完整：一项先例里，抽查出的“错误”有 18–32% 其实是标注者漏标。每轮抽一批“模型抽到而金标没有”的条目做裁决。
- 30 对叙事变化的试标什么也判断不了。建议从 Phase 0 拿掉，等 Benchmark v0 做完再单独试标 100 对。Phase 0 的试标量降为 100 对指引、两轮，每轮约 7 小时。

### 5. 统计设定

- 测试集规模由区分度试跑测到的分歧率决定。500–800 对只在分歧率不超过 15% 时成立；25% 时单个对比就要 785 对。
- 确证性对比预先点名，多重比较用 Holm。
- 只按公司聚类。干净窗口只有两到四个季度，季度当作分层。
- 交互项用条目级的混合 logit 估计，并按难度分层报告。
- 目标 C 的非劣效检验放在没到顶的分层上做，并写明功效：800 对、界值 5 个百分点时，真实差距为 0、1、2 个百分点对应的功效是 0.95、0.83、0.59。
- fine-tuning 那一档的训练 prompt 要和所在组合一致：用检索的组合，训练时就带上正确段落和干扰段落。先不带上下文微调、再加检索，本身会拉低准确率。
- 选 checkpoint、搜 LoRA 超参、改 prompt 都计入开发评估次数。不在测试集上做任何选择。

### 6. 记忆探针和时间戳

- 记忆探针重新设计。模型对截止日前一两年的事实本来就记得很少，只比较截止日前后相邻的季度看不出差别。新设计：只给公司名和财季；选项里有“不知道”；本地模型取答案 token 的概率，商业模型重复采样；季度从截止日前至少三年取到截止日之后；按公司规模分层；和“沿用上期”的基线比较。测不出记忆只说明下限，不能据此称为干净。
- 增加一项条目级检验：开卷抽取是否正确，对闭卷回忆倾向做回归。文献里没有人检验过记忆是否抬高抽取任务的准确率。
- 本地 git 提交不是独立的时间戳。预注册和封存清单需要推送，或者用外部时间戳。仓库可见性的决定因此有了期限：2027-01-10 之前。
- 商业模型的结果标为“干净（以厂商公布的截止日为准）”。
- 按年份截断训练的小模型不再作为参照：上下文最长 2,048 token，最新只到 2024 年，做不了抽取。

### 7. Failure 分层

- 四类 8-K 条目保留为硬事件层，普查按子项做并给出公司数作分母。四类各有要注意的地方：3.01 包含可补救的缺陷和自愿转板；2.06 不含编制定期报告时认定的减值；1.03(b) 是重整计划获批；4.02 到 2012 年只覆盖 35% 的重述。
- 软一层的定义可以写进预注册草案：申报文件锚定的事件（审计师的持续经营疑虑段落、因故退市完成、任何重述、按申报值的减值）；按申报值计算的盈利与杠杆综合指标下滑；含退市收益的 12 个月市场调整收益。
- 文本信号要打败的结构化基线是 Campbell–Hilscher–Szilagyi 的八变量模型，它需要含退市公司的日频价格。
- EXP-0001 写明预期事件数：按每年 0.3–1.5% 的破产率，800 家公司一年只有 2–12 起。封存预测里“六个月内是否出现硬事件”只做描述，主目标是下一季指引方向。
