# narrative-lab 计划：仓库落地 + Phase 0（文献综述与研究设计）

## Context

方案 v0.1 定下了三个研究目标（A 叙事提取、B 适配方法比较、C open-weight 与商业模型比较）和四个阶段，同时把 Failure 的定义、数据源、首批任务、方法如何公平比较都留作开放问题，并明确下一步是 Literature Review 和 Research Design，而不是 fine-tuning。仓库目前是空的。

本计划做两件事：

1. 把仓库搭成研究载体，沿用你在 RE_search 里已经成型的研究登记惯例。
2. 在方案的阶段 I 之前加一个 **Phase 0**，把开放问题收敛成一份有证据支撑的研究设计 v1.0 和第一版 Benchmark 的规格。Phase 0 不训练用于评测的模型。

计划经过两路核对：我通读了 ResearchOS、learning_ai、RE_search 里可复用的部分；另有一份不看我草稿的独立设计，两者在数据源、首个任务、方法比较的设计上结论一致，分歧处我采纳了它更严格的做法（见“五点调整”）。

## 对方案 v0.1 的五点调整

1. **先定能下什么结论。** Level 1 做确证性结论。Level 2 只做有数值锚的版本，例如“指引说利润率上行”对照下一季按申报值计算的利润率。Level 3 定为探索性。原因是功效：按月度 IC 0.02、标准差 0.10 估算，t 值到 2 需要约 100 个月的干净样本，而干净窗口每年只增加 12 个月；硬事件基础概率低，50 个事件的 AUC 区间约为 ±0.08。ResearchOS 每次十几个 case、区间都跨零，是同一个问题。
2. **阶段 I 只做一个任务族：业绩指引修订。** 它的标签能从数值算出来再人工核对，一个人就能标；数据全在 EDGAR，覆盖真正会出事的小盘股；“标题乐观，指引却下调或悄悄撤掉某个指标”本身就是 Failure Detection 的原型。语气、信心变化、管理层与分析师分歧这类构念，没有单个标注者能给出的客观真值，在它们上面测 Level 1，测到的只是和 teacher 模型的一致程度。它们要先在试标里证明单人标注可靠，才进 benchmark。
3. **Phase 0 是三条并行的线，外加一件有时限的事。** 研究设计同时受三组事实约束：已有研究回答了什么、能拿到什么数据、这台机器能跑什么。有时限的事是封存：2026 年三季报对应的下一季结果从 2027 年 1 月中旬开始公布，在那之前把零样本预测封存下来，就多一组真正的前瞻数据。EDGAR 的文档永远在，结果公布前的窗口过了就没了。
4. **目标 B 的核心证据来自 open-weight 模型上的析因实验。** 商业模型的 fine-tuning 要么没有、要么不透明，没法和另外三种方法在同一个基础模型上对比。所以各方法的独立贡献和相互作用在固定的本地基础模型上估计，商业模型跑不含 fine-tuning 的那部分，作为能力参照。由此，LoRA 在 32 GB 上能跑多长的序列是目标 B 的前提，要在 Phase 0 测出来。
5. **不靠脱敏，靠时间；benchmark 做成滚动的。** 测试集一律取自所有评测模型截止日之后的文档。否则记忆会抬高准确率，而且偏向大模型，直接污染目标 C 的比较。正面比较的结论会随模型换代过期，能留下来的资产是一个每个财报季都新增一批干净样本的 benchmark。

明确推迟的内容：电话会纪要上的任务、收益预测、内部表示分析、模型路由与混合架构、并入 ResearchOS。它们留在方案里，等阶段 I 和 II 有结果后重排优先级。

### 工作包 0：仓库落地

`AGENTS.md` 写硬规则：as-of 防火墙，唯一的时钟是 EDGAR 受理时间；先预注册再碰结果数据；测试集只开一次；评测中的模型不得联网检索，输入只来自冻结语料；授权文本、金标测试标签和密钥不入库；一次只跑一个 MLX 任务；每个数字可追溯到脚本和运行记录。

### 工作包 1：文献综述（我做，你审）

按“它要定哪个设计决策”组织，不按主题罗列。

| 线 | 它要回答的问题 | 起点 |
|---|---|---|
| 金融文本分析（LLM 之前） | 哪些叙事特征已被证明有预测力，对什么结果，效应多大；我们必须打败哪些基线 | Loughran–McDonald 2011；Cohen–Malloy–Nguyen 2020；Hassan et al. 2019 |
| LLM 提取金融信号 | LLM 比词典和 FinBERT 多了什么；别人怎么评估 | Lopez-Lira–Tang 2023；Kim–Muhn–Nikolaev 2024；Jha et al. 2024 |
| look-ahead 与记忆 | 什么评估协议站得住 | He et al. 2025 ✓；Glasserman–Lin 2023 ✓；Lopez-Lira–Tang–Zhu 2025 ✓；Gao–Jiang–Yan 2025 ✓ |
| 金融 NLP benchmark | 能复用什么，真正缺什么，别人怎么标注 | FinanceBench；FinQA；FinBen；arXiv 2510.03195 ✓；arXiv 2510.23464 ✓ |
| 适配方法比较 | 怎样公平比较，已知的混淆因素 | Ovadia et al. 2023；Balaguer et al. 2024；Li et al. 2023 ✓ |
| 困境与失败预测 | Failure 怎么操作化，基础概率，结构化基线 | Altman 1968；Beneish 1999；Campbell–Hilscher–Szilagyi 2008 |
| 统计方法 | 多重检验；用 LLM 标签做有效推断 | Harvey–Liu–Zhu 2016；Angelopoulos et al. 2023 |

✓ 表示今天已对照原文摘要核对；其余来自我的记忆，进入综述前逐条核对。

- 做法：每条线检索、粗筛 10–15 篇、精读 3–5 篇，按固定模板记笔记（问题、数据、方法、结果变量、效应大小、如何处理 look-ahead、对我们哪个决策有用）。
- 停止规则：粗筛以 50 篇为上限；连续两批新文献不再改变任何设计决策就停。

### 工作包 2：数据审计

| 需要 | 首选来源 | 要核实什么 |
|---|---|---|
| 披露文本：8-K 业绩新闻稿、10-Q、10-K | SEC EDGAR | 受理时间戳、附件解析、访问频率限制 |
| 电话会纪要 | Hugging Face 的 `kurry/sp500_earnings_transcripts` | 来源和许可是否站得住、是否截断、是否含已被剔除的成分股 |
| 按申报时点的基本面 | SEC XBRL company facts | 是否为首次申报值，重述如何处理 |
| 失败事件 | 8-K 条目代码：1.03 破产、3.01 退市通知、4.02 财报不可依赖、2.06 重大减值 | 能否批量取到，基础概率多大 |
| 含退市股票的收益率 | 待定；免费源通常丢掉退市股票，ResearchOS 用的 IBKR 日线是否覆盖退市股票待核实 | 覆盖和费用；拿不到则 Level 3 只做存活样本并写明偏差 |
| 一致预期 | 批量来源多半收费 | 拿不到则“盈利下修”这个终点改用已实现基本面 |

两个普查决定 benchmark 做不做得成：

- 指引普查：50 家公司 × 8 个季度，数出含数值指引的新闻稿占比和各类变化的比例。
- 硬事件普查：四类 8-K 条目在 2026-06-30 之后各有多少。

每个来源做一次小样本拉取（几十篇，存外置盘），检查时间戳、覆盖和许可。

### 工作包 3：可行性探针（按模型分组，夜间排队，一次一个）

1. 长上下文推理：Qwen3.5-4B 和 9B 在 4k、8k、16k、32k prompt 下的 prefill 速度、decode 速度、峰值内存。
2. LoRA：`mlx_lm.lora` 在 4B 和 9B、序列长度 1k、2k、4k、8k 下的峰值内存和每步耗时，用公开文本。这是工程测量，不产出用于评测的模型。
3. 区分度试跑：100 对文档上比较规则基线、Qwen3.5-4B、9B、Gemma 4 12B、DianJin 和商业模型。通过条件在试跑前写进 registry：规则基线明显落后，最强模型没到顶；如果 4B 已经超过 90%，换更难的分层。试跑同时给出模型之间的分歧率，用于功效估算。
4. 记忆探针：闭卷问模型某公司某季度的指引，比较截止日前后的正确率。
5. 结构化输出的合规率、证据引文的逐字命中率、工具调用的可靠性。

探针直接在 `py313` 里跑，不下载新模型。商业模型部分的预算参照 ResearchOS 记录的每 case 约 $0.16–0.22，在试跑里实测。

### 工作包 4：标注试标

- 标注手册定义指引元组（指标、期间、下限、上限、口径）和变化类别（上调、维持、下调、收窄、撤回或不再提及、首次给出）。
- 变化类别由元组按规则算出，你核对。评测名单里的模型不参与测试集标注；商业基线多半是 Claude 系列，所以金标不能由我来标。
- 只有一位标注者，用同一批 100 对间隔 14 天重标的一致性代替标注者间一致性。建议阈值：重标 kappa 不低于 0.8，规则与人工的一致率不低于 90%。
- 顺带试标 30 对“跨季度叙事变化”。达不到同样的阈值，这类任务就不进 Benchmark v0。

### 工作包 5：封存账本

- 评测名单：本地模型记 Hugging Face repo 和 revision，商业模型记模型 ID。
- 样本：2026 年三季报里给了数值指引、且下一次业绩发布在封存日之后的公司。
- 预测目标：下一季指引方向；六个月内是否出现硬事件。
- 用固定的零样本 prompt，登记为 EXP-0001，先预注册。预测内容存外置盘，仓库只提交哈希清单。落盘布局沿用 ResearchOS 的先封存、后揭晓。

### 工作包 6：研究设计 v1.0

把前五个工作包的结果写成 `research_design.md`：数据源与样本范围、Benchmark v0 规格、划分、方法比较的实验设计、各 Level 的终点与功效估算、Failure 的预注册定义、PIT 规则。每个决策写明证据出处和“什么结果会推翻它”。硬规则写进 `00_master_methodology.md`；方案更新为 `docs/proposal/v0.2.md`，v0.1 不改。

## 设计的默认假设

下表是现在的建议，用来给文献综述和数据审计定靶子。Phase 0 的任务就是证实或替换它们。

| 决策 | 默认 | 什么会推翻它 |
|---|---|---|
| 文本源 | EDGAR：8-K 业绩新闻稿（Item 2.02 的附件 99.1），加 10-Q、10-K。纪要只作私有的第二层 | 纪要的许可审计通过且质量好 |
| Benchmark v0 | 业绩指引修订，三个子任务：抽取指引元组；判断变化类别；对照对（只改数字或只改措辞，标签由构造决定）。含定性指引的分层，例如“预计落在区间低端” | 普查显示含指引的新闻稿太少；或文献里已有可复用的同类 benchmark |
| 分析单位 | 同一公司相邻两期新闻稿的 outlook 段落对；整篇文档只在稳健性子集上跑 | 探针显示整篇推理和训练都宽裕 |
| 规模 | 金标测试集 500–800 对，至少 400 家公司；训练集用规则标注，取自更早时期和不同公司 | 试跑的分歧率改变功效估算 |
| 划分 | 测试集取所有评测模型截止日之后的文档，目前是 2026-06-30 之后；训练集更早，且公司不重叠 | 名单里加入截止日更晚的模型 |
| 方法比较 | Qwen3.5-4B 和 9B 上的全析因：prompt、fine-tuning、工具各两档，检索三档（无、检索到的、直接给出正确段落），共 24 个组合，每条测试样本跑遍所有组合。每种方法用同一个开发集和相同次数的开发评估。交互项在 logit 尺度上、按难度分层估计，避免天花板造成“互相替代”的假象 | LoRA 探针失败，则 fine-tuning 降到更小的模型 |
| 目标 C | 把最优的本地配置和每个商业模型做非劣效检验，界值预先设定（建议 5 个百分点），并报告每千条的成本和延迟。DianJin-R1-7B 作为“别人已做过领域训练”的对照。4B 用 8-bit 重跑一次，估计量化带来的偏差 | 无 |
| 终点 | 主要：干净文档上变化类别的配对准确率差。次要：元组 F1、对照对一致性、校准、成本。探索性：硬事件关联、封存预测的 Brier | 无 |
| Failure 定义 | 硬事件这一层现在就定为四类 8-K 条目；其余层次在看结果数据之前预注册 | 文献里有更好的操作化 |
| 结果标注 | 每个结果带一个标签：干净（截止日之后，或反事实改写）、有界（截止日之前但标签由给定文本决定，同时报告记忆探针的差距）、受污染（只作上界）、前瞻（封存预测） | 无 |

规模的依据：两个系统在 15% 的样本上结论不同时，要以 80% 的功效检出 5 个百分点的差异，需要约 470 对；对 10 个对比做校正后约 800 对。
