# Synthetic Data Generation Using Large Language Models for Financial Question Answering

- **Citation:** Harsha, C., Phogat, K. S., Dasaratha, S., Puranam, S. A., Ramakrishna, S. (2025).
  Proceedings of the Joint Workshop of the 9th FinNLP, the 6th FNP and the 1st LLMFinLegal,
  Abu Dhabi, January 2025, pp. 76-95. Version read: ACL Anthology PDF (full text,
  including appendices A-F), text extracted locally from the PDF.
- **Link:** https://aclanthology.org/2025.finnlp-1.7/ (PDF: https://aclanthology.org/2025.finnlp-1.7.pdf)
- **Stream:** 14a (teacher-generated synthetic data for small domain specialists)
- **Verified against source:** yes, 2026-11-25, against the Anthology page and the full PDF text.
  Tables were read from extracted text whose layout was scrambled; the values below were matched
  to the text's own statements (for example "within 5% ... for the PHI-3 models") and to the
  real-data numbers of `phogat-2024`, which they reproduce.

## Question

Can questions and reasoning programs generated by a large model from the same financial report
pages replace expert-written FinQA, TATQA and ConvFinQA training data for fine-tuning small models?

## Data

The page images (FinQA, from S&P 500 annual reports 1999-2019 via FinTabNet) and hybrid text-table
contexts (TATQA, about 500 reports) used by the original data sets. Synthetic set sizes equal the
real training splits: FinQA 6,251, TATQA 4,992 (arithmetic questions only), ConvFinQA 2,737. Test:
FinQA test 1,147; TATQA and ConvFinQA dev splits (718 and 421) used as test. The text read does not
say whether pages behind the test splits were excluded from generation.

## Method

- Teacher and generator: GPT-4o, temperature 0.7 for questions (several distinct questions per page,
  earlier questions in the prompt to force variety), temperature 0 for the answer, written as Python
  (zero-shot program of thought).
- Two prompt variants: zero-shot with constraints on operations and answer type; the same plus a few
  real example questions (no contexts).
- Filter: drop pairs whose code does not run or returns a non-scalar or a value of the wrong type.
  No check of financial correctness.
- Conversational data: "derived" (split a generated question into sub-questions) or "direct" (ask
  for 2-5 linked sub-questions from the page).
- Students: Phi-3-mini (3.8B), Phi-3-medium (14B), Mistral-7B-Instruct-v0.2; same LoRA recipe as
  `phogat-2024`, 4 epochs, last epoch evaluated. Answers by executing the generated program.

## Outcome variable and horizon

Execution accuracy against the gold answer. No horizon.

## Result

- **Empirical finding, synthetic against real (Table 1, FinQA test):** Phi-3-mini 68.43
  (synthetic, zero-shot prompt) and 68.09 (with example questions) against 73.49 (real);
  Phi-3-medium 73.49 and 73.58 against 77.59; Mistral 7B 67.21 and 68.09 against 76.63. TATQA:
  Phi-3-mini 88.99 / 87.74 against 90.94; Phi-3-medium 90.80 / 90.66 against 93.03; Mistral 88.44
  / 88.85 against 88.71. Example questions in the prompt changed almost nothing.
- **Empirical finding, transfer to the other data set (Tables 2-3, Phi-3-mini):** trained on full
  synthetic FinQA, TATQA test 84.26 against 81.19 when trained on full real FinQA; trained on
  synthetic TATQA, FinQA test 67.82 against 63.81 from real TATQA. Real data improved only its own
  test set as it grew; synthetic data improved both.
- **Empirical finding, data size (Phi-3-mini, FinQA test):** synthetic 750 / 1,500 / 3,000 / full
  = 63.99 / 64.95 / 68.61 / 68.43; real = 69.83 / 71.31 / 71.49 / 73.49. Gains flatten after about
  3,000 examples in both.
- **Empirical finding, similarity to real questions (Table 4):** 750 synthetic questions nearest
  to real ones against the 750 farthest: within 2 points of a random 750 on both tests.
- **Empirical finding, generator bias:** an audit of 50 synthetic FinQA questions found under 5%
  were text-only or Boolean; the smaller students trained on synthetic data underperformed most on
  text-only and Boolean test questions (Tables 9-10, values not re-keyed).
- **Empirical finding, conversations:** synthetic conversational data falls short, most on hybrid
  conversations; mixing real data closes the gap for Phi-3-mini on ConvFinQA (overall 69.98 with
  10% real, 73.07 with 20%, 74.87 with 40%, 76.00 all real, same total size).
- No intervals, seeds or significance tests. On 718-1,147 test items a 95% interval is roughly
  ±2.5 to ±3.5 points (my calculation), so differences of 1-3 points are not established.

## Look-ahead and memorisation

Not addressed. Data sets predate all models; whether test pages fed generation is not stated in the
text read; no overlap check between synthetic and test questions beyond the embedding-distance
analysis against training questions.

## What it settles for us

- The closest finance evidence that a large model generating questions and worked answers *from
  the filings themselves* can stand in for expert-written training data for a small model, at
  3.8B-14B and on numeric QA. It does not test anything below 3.8B, nor label or judgement items.
- **Directly relevant to S1's template lock-in.** The generator's own bias (almost no Boolean or
  text-only questions) reappeared as a student weakness on exactly those types. S1's distilled 0.8B
  boxes a number on 300/300 label items after training only on numeric answers; the paper shows the
  same mechanism one step earlier, at the level of what the generator chooses to ask. A synthetic
  set for S1 needs a quota by answer type and question type, set before generation and audited
  after (hypothesis for S1).
- Synthetic data generalised across data sets better than real data of the same size (about +3 to
  +4 points), which the authors attribute to broader question variety (hypothesis in the paper).
- Volume: no gain past about 3,000 examples on one task family at 3.8B. "More of the same" stops
  paying early; more *kinds* of question is the untested lever.
- A small share of gold-checked items (10-20%) recovers most of the gap where synthetic data is
  weakest. For S1, the rule-labelled EarningsExam items can play that role.
- Reusable: the four-step pipeline (page, question, program, execution filter), the "different from
  previous questions" prompt trick, the nearest-neighbour audit.

## Limits

One teacher (GPT-4o); students of 3.8B and up; numeric QA only; filter checks executability and
type, not correctness; single runs; same company documents as the test sets; the authors' firm
(EY) built both the real-data baseline paper and this one.
